English · [Tiếng Việt](AUDIT.vi.md)

## 2. Architecture

Details in [ARCHITECTURE.md](ARCHITECTURE.md). Summary of the assessment:

- **Layers:** View → Store (`@MainActor @Observable`) → service protocol → Service (static enums / `Sendable` structs). Services do not import SwiftUI.
- **MVVM:** `AppStore` is the composition root (profiles, Docker data, connection / events, navigation). Long operations live in `OperationCenter`; each screen has its own model (`ContainersModel`, `RuntimeModel`, `DiagnosticsModel`, …) (T7).
- **DI:** Views obtain Stores via `@Environment`. Stores reach Docker and Colima through the `DockerEngine` / `ColimaControlling` protocols, injected via `AppServices`, with in-memory fakes for tests (T6). Background stores depend on narrow host protocols instead of `AppStore` (T8).
- **Concurrency:** UI state on the MainActor; blocking I/O on GCD via `BlockingIO`; timeouts and cancellation for processes and sockets.
- **Real-time:** Docker `/events` coalesced over 300 ms, kqueue on `_lima` debounced 600 ms, 30 s fallback polling.

No leaking retain cycles found: `Task`s capture `AppStore`, but the Store lives for the whole app lifetime. No races on UI state, since all of it is on the MainActor.

## 3. Technical risks addressed in the 1.0.0 design

Locations name the file and the symbol, so they survive edits.

| # | Severity | Risk | Mitigation in 1.0.0 | Location |
|---|---|---|---|---|
| R1 | P0 | Blocking I/O (`recv`, waiting on processes) occupies the cooperative thread pool and can stall every async task | `BlockingIO.run` runs blocking work on a dedicated concurrent `DispatchQueue`; `ProcessExecution` reads pipes on GCD and waits via `terminationHandler` | `Core/BlockingIO.swift` (`BlockingIO`), `Core/Docker/DockerClient.swift` (`connection`), `Core/Shell.swift` (`ProcessExecution`) |
| R2 | P0 | A hung process (e.g. `colima ssh`) has no timeout, cannot be cancelled, and leaves orphaned processes | `Shell.run` has a timeout (default 120 s, colima 15–30 s); cancelling the Task calls `terminate()`; errors `ShellError.timedOut` / `CancellationError` | `Core/Shell.swift` (`Shell.run`, `ProcessExecution.run`) |
| R3 | P0 | Docker requests cannot be cancelled and must wait for `SO_RCVTIMEO` to expire | `SocketHandle` calls `shutdown(fd, SHUT_RDWR)` when the Task is cancelled | `Core/Docker/DockerClient.swift` (`SocketHandle`) |
| R4 | P0 (data safety) | Backup swallows write errors (disk full), producing a truncated tar file reported as success; a mid-way failure leaves a partial file | `receiveToFile` writes a 0600 temporary file in the same directory, incremental SHA-256, `synchronize()`, then replaces the destination; on failure the temporary file is deleted. `AtomicFile` for manifests / logs | `Core/Docker/DockerClient.swift` (`receiveToFile`), `Features/Backup/BackupService.swift` (`AtomicFile`) |
| R5 | P0 | Hardcoded Docker socket path, wrong when Colima moves the socket | Read `docker_socket` from `colima status --json`; fall back to `$COLIMA_HOME/<profile>/docker.sock` | `Core/Colima/ColimaService.swift` (`status`, `resolveDockerSocket`), `App/AppStore.swift` (`resolveEndpoint`) |
| R6 | P1 | Long-running operations cannot be cancelled; a process killed by a signal is treated as success | Cancel button with confirmation in `OperationPanel`; separate `cancelled` state; `Shell.stream` treats exit by signal as an error | `Core/Shell.swift` (`uncaughtSignal` branch in `Shell.stream`), `App/OperationCenter.swift` (`runOperation`), `UI/Components.swift` (`OperationPanel`) |
| R7 | P1 | The log viewer reassigns the whole string (up to 2 MB) on every update and re-lays out the entire document | `CodeTextView` appends only the new part to `NSTextStorage` when the content only grows | `UI/Components.swift` (`CodeTextView`) |
| R8 | P1 | A new formatter is created on every cell render | Shared static formatters in `Format` | `Core/Utilities.swift` (`Format`) |
| R9 | P1 | `Shell.which` ignores `PATH` (MacPorts, Nix) | Searches Homebrew paths, then the process `PATH`; rejects names containing `/` | `Core/Shell.swift` (`Shell.which`) |
| R10 | P2 | One failing Docker endpoint blocks updates of other data types | `AppStore.reload` loads each type independently | `App/AppStore.swift` (`reload`) |
| R11 | P2 | The Exec transcript grows without bound | Trimmed to 250,000 bytes when it exceeds 500,000 bytes | `Features/Containers/ContainersView.swift` (exec transcript) |
| R12 | P2 | Backup helper containers left behind when the app is killed mid-operation | `VolumeBackup.cleanupStaleHelpers` removes helpers with label `dev.colimax.helper`, state `created`, older than 10 minutes, on every Docker connection | `Features/Backup/BackupService.swift` (`cleanupStaleHelpers`) |

All paths are relative to `Sources/ColimaX/`.

Test coverage: R1–R4, R6 and R9 have unit tests in `ShellTests` / `DockerClientTests` / `OperationTests`. R3 (log stream cancellation), R4 (file transfer), R5 (endpoint) and R12 (`testCleanupStaleHelpersOnlyRemovesTestHelpers`) are covered by integration tests. R7, R8, R10 and R11 have no automated tests.

## 4. Open items

None. Items found by the review and since resolved: per-screen models split out of `AppStore` (T7); service protocols with fakes (T6); UI tests for destructive confirmations and secret masking (T9, T10); MySQL / MariaDB / PostgreSQL backups run against real containers (G9); confirmation before stopping / restarting the VM while containers run (`VMControl`; stopping a single container stays one click, since Start undoes it); localization (G18); app icon (T4).

## 6. UX / UI

- **Strengths:** `NavigationSplitView` with a four-group sidebar; sortable `Table`s; context menus; `ContentUnavailableView` for empty states; confirmation for destructive operations; System / Light / Dark themes; ⌘1…⌘9; Diagnostics and Security combined on one screen; Storage offers cleanup actions with confirmation; health icon in the Status column of Containers.
- **Limitations:**
  - errors are shown mostly through a generic banner;
  - restart count is visible only in the details pane, with no dedicated column.
